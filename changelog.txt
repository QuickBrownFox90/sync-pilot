== Changelog ==

= Version 0.0.2 =

* Changed: The Help tab is reduced to a "Diagnostics" tab — only the diagnostic info and the error log with "Clear Error Log" remain; the support link and the demo videos (the original screencasts of WP Sync DB showing its old user interface) are removed together with their JavaScript and CSS; the template is now `template/diagnostics.php`, the tab hash is `#diagnostics` (was `#help`), and the error messages #105, #106, #108 and #118 point to the Diagnostics tab and the error log instead of "the Help tab for details on how to request support"
* Changed: The text domain is no longer repeated as a string literal in every gettext call but taken from the class constant `SyncPilot_Base::TEXT_DOMAIN` (`self::TEXT_DOMAIN` in classes and templates), so it can be changed in one line; the `Text Domain:` plugin header stays a literal, as WordPress reads it without executing PHP
* Added: German translation (`languages/sync-pilot-de_DE.po` and `.mo`, informal "du"); the source language is English
* Removed: `languages/sync-pilot-en.pot` — it was outdated and a template is not needed at runtime; the translations are shipped as `.po` and `.mo` directly
* Fixed: `e()` instead of `_e()` in the message "Could not delete the MySQL export file." would have ended in a fatal error "call to undefined function" if deleting the export file failed
* Fixed: The diagnostic info used the leftover text domain `wp-app-store` for "ext/mysqli" and "WP Memory Limit"
* Changed: The plugin header is written as a docblock with a leading ` * ` on every line and requires PHP 8.2 (was 8.1); the version is raised to 0.0.2 in the header, in `$GLOBALS['syncpilot_meta']` and in the MU compatibility plugin
* Fixed: `backquote()` used `each()`, which was removed in PHP 8.0 and would have ended in a fatal error if the function was called with an array; it now uses `foreach`
* Fixed: The diagnostic info called `mysql_get_server_info()` (removed in PHP 7) as a fallback when mysqli was not in use; the MySQL version now comes from `$wpdb->db_server_info()`
* Removed: Code for PHP's `safe_mode`, which does not exist since PHP 5.4 — the "PHP Safe Mode Enabled" notice (it never showed, because `$safe_mode = ini_get(…) && …` bound wrongly), the filter `syncpilot_hide_safe_mode_warning` and the `safe_mode` check before `set_time_limit()` (now only `function_exists( 'set_time_limit' )`)
* Removed: The "Internet Explorer Not Supported" notice and the script that showed it; the two strings are removed from the German translation
* Fixed: The status in the README named a version "2.0.0-dev" left over from an earlier draft; it now says 0.0.2 (alpha)
* Fixed: The release workflow read the version only from header lines that start with `Version:` and would have refused to build after the header got the leading ` * `; it now accepts both forms
* Changed: Code style of `class/syncpilot.php` — more air between logical groups, aligned assignments, no braces around single statements; no functional change
* Known issue: Not everything is translatable yet — the words "local" and "remote" that the JavaScript inserts into sentences (`asset/js/media-files.js`, `asset/js/script.js`) and the placeholders "New URL" and "New file path" of the find & replace fields are hard-coded English

= Version 0.0.1 =

* Added: First test release of SyncPilot (private, version 0.0.1; the first public release is planned as 1.0.0 once the changes of the 0.x versions have been tested on several installs) — a fork of WP Sync DB 1.5 (itself a continuation of WP Migrate DB by Delicious Brains, last maintained in 2014) merged with WP Sync DB Media Files 1.1.4b1; functionally identical to those two plugins, rebranded and merged into one
* Changed: The Media Files addon is now part of the plugin — `SyncPilot_Media_Files` extends `SyncPilot_Base` directly and is loaded by `sync-pilot.php` right after the core class, so the migration form, the "Media Files" option and the AJAX handlers are always available; the `WPSDB_Addon` class (`class/wpsdb-addon.php`), the addon registry in the base class (`$this->addons`, `is_addon_outdated()`), the "addon out-of-date" admin warning and the second plugin header with its `version.php` are removed, as there is no separate addon whose version could mismatch
* Changed: Everything is renamed from `wpsdb` / `wp-sync-db` to `syncpilot` / `sync-pilot` — classes (`SyncPilot`, `SyncPilot_Base`, `SyncPilot_Media_Files`), functions, option names (`syncpilot_settings`, `syncpilot_error_log`), AJAX actions (`wp_ajax_syncpilot_*`, media files: `syncpilot_mf_*`), nonces, filters and actions, the `$GLOBALS['syncpilot_meta']` array, JS variables and script handles, CSS classes, the admin menu slug (`page=sync-pilot`), the text domain and the file names (`sync-pilot.php`, `class/syncpilot*.php`, `compatibility/sync-pilot-compatibility.php`, `languages/sync-pilot-en.pot`); this is a deliberate clean break, so both sides of a migration need SyncPilot and a remote site still running WP Sync DB cannot be reached
* Changed: The media files script is enqueued as `sync-pilot-media-files` — a plain rename would have given it the same handle as the core script (`sync-pilot-script`), which would have made it depend on itself and never load; the media files options form moved from `template/migrate.php` to `template/media-files-options.php` and its script from `asset/js/script.js` to `asset/js/media-files.js`
* Added: One-time import of WP Sync DB settings — on the first load `SyncPilot_Base::migrate_legacy_settings()` copies the `wpsdb_settings` option (API key, pull/push permissions, saved profiles, plugin blacklist) to `syncpilot_settings` if the latter does not exist yet, and records the time in `syncpilot_legacy_migrated`; the old option is only read, never changed or deleted, so WP Sync DB can stay installed side by side until the switch is complete
* Changed: Plugin header — author, `Requires PHP: 8.1`, `Requires at least: 6.0`, `Domain Path`; the plugin title shown in the admin is now fixed to "SyncPilot" instead of being derived from the file name; the MU compatibility plugin (`sync-pilot-compatibility.php`) is renamed, so a compatibility plugin installed by WP Sync DB (`wp-sync-db-compatibility.php`) is not replaced and keeps acting only on `wpsdb*` requests
* Changed: Help tab — the support link points to the author's website instead of the GitHub issue tracker of the original project; the demo videos are still the original screencasts of WP Sync DB and show its old user interface
* Removed: `github-updater` installation instructions and the `GitHub Plugin URI` header of the original plugin; `composer.json`, `composer.lock` and `vendor/` (only `composer/installers`) of the Media Files addon, which are not needed at runtime
* Added: Release workflow (`.github/workflows/release.yml`) — publishing a GitHub release builds `sync-pilot.zip` with the correct `sync-pilot/` root folder and attaches it to the release; the workflow refuses to build if the version in the plugin header differs from the release tag
* Verified: Pull and push between two installs on PHP 8.4 including the media files option (originals, thumbnails and WebP variants transferred with matching file sizes), "Remove local media", find & replace of the site URL, and the import of existing WP Sync DB settings
* Known issue: Not yet verified — pulling new media files (only push was tested with new files), the SQL export download, multisite (the multisite code paths of the media files class have not been run) and the WP-CLI integration
* Known issue: The code base dates from 2014 and has not been audited for PHP 8.x deprecations or warnings with `E_ALL` yet; no messages from SyncPilot appeared in the admin area of the test installs, but not every screen and code path has been exercised
* Known issue: `languages/sync-pilot-en.pot` was renamed by text replacement and not regenerated, one sentence fragment still reads "Sync DB"; the link to the find & replace documentation (`template/migrate.php`) is the unchanged link of the original plugin and probably no longer works
